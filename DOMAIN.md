# Домен www.productmike.ru → GitHub Pages

Сайт собирается GitHub Actions (`.github/workflows/deploy.yml`) при каждом push в `main`
и публикуется на GitHub Pages. С 25.10.2026 домен зарегистрирован в REG.RU
(NS `ns1.reg.ru`, `ns2.reg.ru`), DNS-зона — там же. Старая зона на Beget больше не используется.

## Если домен перестал открываться (например, после продления)

### 1. REG.RU: DNS-зона

1. Личный кабинет → Домены → `productmike.ru` → «DNS-серверы и управление зоной».
   DNS-серверы должны быть `ns1.reg.ru`, `ns2.reg.ru` (по умолчанию).
2. Удалить записи парковки REG.RU (A `@` и `www` → `95.163.244.138`), если домен
   показывает страницу «Домен зарегистрирован и припаркован в Рег.ру».
3. Добавить записи:

| Тип   | Имя   | Значение                  |
|-------|-------|---------------------------|
| A     | @     | 185.199.108.153           |
| A     | @     | 185.199.109.153           |
| A     | @     | 185.199.110.153           |
| A     | @     | 185.199.111.153           |
| CNAME | www   | mikeproduct14.github.io.  |

   У `www` не должно остаться A-записи — иначе CNAME не заработает.
   Опционально AAAA для `@`: `2606:50c0:8000::153`, `2606:50c0:8001::153`,
   `2606:50c0:8002::153`, `2606:50c0:8003::153`.

### 2. GitHub: Settings → Pages

1. Source: **GitHub Actions**.
2. Custom domain: `www.productmike.ru` → **Save**. Если поле уже заполнено, удалить домен,
   сохранить и ввести заново — это перезапускает проверку DNS и выпуск сертификата.
3. Дождаться зелёной галочки «DNS check successful» и включить **Enforce HTTPS**
   (сертификат выпускается от нескольких минут до суток).
   После смены DNS-записей проверка GitHub может до суток (TTL записей REG.RU — 86400)
   показывать `InvalidARecordError` по закэшированным старым записям, хотя `dig` уже
   отдаёт правильные. Пока сертификат не выпущен, `https://` отдаёт сертификат `*.github.io`.
   Надпись «DNS Check in Progress» может висеть и после выпуска сертификата — проверяйте,
   открывается ли `https://www.productmike.ru` без предупреждения.
4. Actions → «Deploy to GitHub Pages» → **Run workflow**, чтобы передеплоить.

### 3. Защита от перехвата домена (один раз)

Профиль GitHub → Settings → Pages → **Add a domain** → `productmike.ru`.
GitHub выдаст TXT-запись `_github-pages-challenge-MikeProduct14` — добавить её в DNS-зону на REG.RU
и нажать Verify. После этого никто другой не сможет привязать домен к своему репозиторию,
даже если DNS временно отвалится.

### Проверка

```bash
nslookup www.productmike.ru   # должен вернуть mikeproduct14.github.io
nslookup productmike.ru       # 185.199.108-111.153
```

Файл `CNAME` в корне репозитория при деплое через Actions не используется —
домен задаётся только в Settings → Pages.
